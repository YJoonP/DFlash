# Qwen3.5 DFlash 시행착오 정리 (2026-09 ~ 2026-10-15)

- 작성: 2026-10-16 KST
- 이 파일은 현재 최종본(v5)에 이르기까지의 시도와 실패를 한곳에 모은 것입니다.
- 최종본 설명과 최종 결과는 `REPORT_20261016.md`, 공개 요약은 저장소 첫 화면 README 에 있습니다.
- 모든 DFlash 수치는 b = 16 (블록 크기 16) 이고, b = 8 은 따로 표시했습니다.
- TPS 는 세션마다 프롬프트 수·러너·폰이 달라서, 같은 세션 안의 비교만 의미가 있습니다.

- 각 세션의 원본 기록(요약, run json, 검사 결과)은 연구실 서버에 있습니다. 이 저장소에는 최종 측정(`results/`)만 들어 있습니다.

## 2. 실패하거나 막힌 길, 그리고 이유

| 시도 | 무엇이 문제였나 | 배운 것 |
|---|---|---|
| 비정확 재계산 (옛 채택) | 재료를 저장한 눈금과 다시 읽는 눈금이 달라 커밋이 반올림된 값으로 상태를 만듦. 방식마다 토큰이 다름 | 재계산도 "검증과 같은 값"을 읽어야 함 |
| ckpt5 (b8) | 이득이 없고 정확하지도 않음 (10쌍 중 6쌍 같음) | 체크포인트 행은 수락 분포에 맞춰야 함 |
| HMX DeltaNet 커널 | 구조 검사까지만 가고 중단. 원본의 DMA/HVX/HMX 병렬 파이프라인은 이식하지 않았음 | HVX 커널로 충분한지 먼저 볼 것 |
| exact v1 / exact conv | 정확성은 좋아졌지만 NPU +4.7 / +9 ms | 숫자(눈금)만 바꿔도 컴파일 결과가 크게 달라짐 |
| conv 창 수정 | 저장 방식과 값을 맞추려고 저장 눈금 A, 읽기 눈금 B(5 ppm 차이)를 씀. 층마다 19행×8192 변환 연산이 생기고, 샤드 0 넘침 버퍼가 0.8 → 22 MB | 재계산 = ckpt10 정확성에는 필요 없었음. 목표를 정확히 정하고 고칠 것 |
| ckpt10 v1 | 재료를 헤드 묶음으로 자를 때 눈금이 바뀌어(384곳 중 343곳) 검증 경로와 재생 경로의 반올림이 다름 | 경로 전체를 한 눈금으로 |
| 인코딩 1개 | 16·21층 상태 입력의 읽기 눈금이 1코드 다름. ckpt10 의 쿼리 조각이 따로 보정된 눈금(192개 중 143개) | 상태 입력과 나눈 조각까지 같은 눈금으로 (v3) |
| v4 | 변환 연산은 없앴지만 conv 창 수정의 다른 흔적(넘침 버퍼, 상수 증가)이 남음 | 원인 수정 자체를 빼는 쪽이 나음 (v5) |
| ckpt10 체크포인트 (v3, v5) | 10개 이상 수락이 18~19% 뿐. 정확히 10개 수락이면 "커밋할 행 없음" 경로가 호출당 +23~77 ms. 그래서 켬 = 끔 | 체크포인트보다 검증 연산 나누기 효과가 더 큼 (원인 미확인) |
| 저장 방식 | NPU 가 상태 16개를 내보내고, CPU 쪽에 스냅샷 준비·선택이 3~4 ms 듦 | 재계산(v5)이 단계 시간 기준 10~13% 빠름 |
| QNN linting 프로파일 | 기존 컨텍스트에서 켜면 S25 cDSP 가 멈춤(오류 0x2301) | 컴파일 때 켜야 하는 기능으로 보임 |
| 상세(DETAILED) 프로파일 | 연산별 사이클만 주고 시간은 안 줌. 사이클이 같아도 시간은 다를 수 있음 | 사이클 비교로 시간 원인을 단정하지 말 것 |

## 3. 교훈

1. **같은 값이면 같은 눈금으로.** 저장 눈금과 읽기 눈금이 같으면 16bit → 32bit → 16bit 를 거쳐도 값이 그대로입니다. 문제는 늘 "다른 눈금이 만나는 곳"이었습니다.
2. **몇 ppm 차이도 QNN 에는 다른 눈금입니다.** 변환 연산이 들어가고 메모리 배치까지 바뀌어 NPU 시간이 수 ms 늘 수 있습니다. export 마다 `check_og.py` 로 이런 지점을 셉니다.
3. **정확성은 정적 검사와 기기 시험을 둘 다 봅니다.**
   - 정적 검사: `check_v3.py` (S1~S4), `check_exact*.py`
   - 기기 시험: 강제 토큰 재생 시험(로짓 지문, 커밋된 상태 코드)과 18개 프롬프트 토큰 비교
4. **토큰 동일성은 검증 묶음 크기가 같을 때만 비교합니다.** 묶음 크기를 1/4/16 으로 바꾸면 같은 방식 안에서도 로짓이 약 0.06 달라집니다. 저장 방식과 재계산은 토큰이 같아질 수 없습니다.
5. **러너는 토큰을 바꾸지 않습니다.** 러너를 바꿀 때는 시간만 비교합니다. 다른 날 다른 러너로 잰 TPS 를 나란히 놓으면 안 됩니다.
6. **측정은 같은 세션에서, 설정 순서를 돌려 가며, 쉬는 시간과 온도를 지키며 합니다.** 세션이 다르면 1~2 ms 씩 달라집니다.
7. **체크포인트 이득은 수락 분포에 달려 있습니다.** AL 이 약 5 인 상황에서 10행 체크포인트는 쓸 기회가 적습니다.
